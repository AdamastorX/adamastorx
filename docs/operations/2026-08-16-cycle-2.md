### New finding: `market-data-ingestor`'s 34-restart burst on 2026-08-14

`kubectl logs --previous` on the pod's prior container shows the same
exception recurring **43 times** in that window, from a background
`HttpClient` worker thread (the Finnhub websocket client's own async
I/O), each time bubbling into the process:

```
Caused by: java.lang.ExceptionInInitializerError: Exception org.apache.kafka.common.config.ConfigException:
Invalid value org.apache.kafka.common.security.oauthbearer.DefaultJwtRetriever for configuration
sasl.oauthbearer.jwt.retriever.class: Class org.apache.kafka.common.security.oauthbearer.DefaultJwtRetriever
could not be found.
```

Every exit in this window was `exitCode 143` (SIGTERM, graceful
shutdown), not `137` (OOMKilled) — the pattern matching a
liveness-probe-driven kill, not a resource limit. This is the same
flavor of Boot/Kafka-client dependency-artifact gap `docs/WHY.md`
already names as a recurring class in this project (Kafka, Flyway, and
OTel tracing autoconfiguration each hit a version of it once) — worth
checking whether `kafka-clients` was bumped (Renovate) without a
matching `sasl.oauthbearer` support artifact, rather than assumed to
be unrelated. **Not root-caused further in this cycle** — the pod has
been stable, zero restarts, for the ~2 days since — recorded honestly
as a real, open, previously-undiscovered gap rather than left
unmentioned because it's currently quiet. Tracked as new backlog #140.
